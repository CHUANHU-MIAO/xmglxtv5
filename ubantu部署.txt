## 二、挂载机械硬盘（存放上传文件）

```bash
lsblk
```
查看硬盘和分区，确认机械硬盘设备名（通常是 `sdb`）。

```bash
sudo mkdir -p /data/上传的文件
sudo mount /dev/sdb /data/上传的文件
sudo chown -R xazx:xazx /data/上传的文件
```
创建挂载点，挂载硬盘，并赋予用户写入权限。

```bash
echo '/dev/sdb /data/上传的文件 ext4 defaults 0 0' | sudo tee -a /etc/fstab
```
写入开机自动挂载配置。

## 六、License 授权部署（一键命令，加密验证）

> ⚠️ 必须步骤：系统启动时会验证 `license.key`，无授权文件无法运行。

### 6.1 准备：将授权工具复制到 Ubuntu 服务器

在管理机（Windows）上将以下两个文件复制到 Ubuntu 用户家目录（有写入权限）：

```bash
# 把 192.168.1.100 替换为你 Ubuntu 服务器的实际 IP（ip addr 查看）
# 传到用户家目录，不用 sudo，不会报权限错误
scp D:\系统部署\license_generator.py xazx@192.168.1.100:~/
scp D:\系统部署\private_key.pem xazx@192.168.1.100:~/
```

> 💡 也可以用 WinSCP、FileZilla 等工具拖拽到用户家目录，无需敲命令。

然后在 Ubuntu 上把文件挪到 `/opt/`（需要 sudo）：

```bash
sudo mv ~/license_generator.py /opt/
sudo mv ~/private_key.pem /opt/
```

> 📦 两个文件只需复制一次，后续续期无需再次复制。

### 6.2 安装加密库

```bash
source /opt/kyglxtv3/venv/bin/activate
pip install cryptography
deactivate
```

### 6.3 一键授权（核心步骤）

```bash
python3 /opt/kyglxtv3/license_generator.py --auto-deploy /opt/kyglxtv3
```

执行过程：
1. 自动读取 Ubuntu 设备指纹（MAC + 磁盘序列号 + CPU序列号）
2. 显示设备信息
3. 提示输入授权到期日期（回车默认一年）
4. 用私钥签名，自动生成 `license.key` 写入项目目录

预期输出示例：
```
============================================================
  河北鑫奥项目管理系统 - 一键部署
============================================================

设备信息：
  计算机名:  ubuntu-server
  设备指纹:  f3a2b1c4d5e6789012345678abcdef01
  MAC地址:   00:11:22:33:44:55
  CPU序列号: 0000000000000000
  磁盘序列号: WD1234567890

授权到期日期 [默认: 2027-05-19]:

部署完成！
  License文件: /opt/kyglxtv3/license.key
  到期日期:    2027-05-19（剩余 365 天）
  指纹:        f3a2b1c4d5e6789012345678abcdef01

系统启动时将自动验证授权。
============================================================
```

### 6.4 验证 License

```bash
cd /opt/kyglxtv3
source venv/bin/activate
python3 -c "from license_manager import verify_license; valid, msg = verify_license(); print(msg)"
deactivate
```

预期输出：`授权有效，剩余 365 天（到期日：2027-05-19）`

### 6.5 License 续期

到期后，在服务器上再次执行一键命令即可覆盖旧 License：
```bash
python3 /opt/license_generator.py --auto-deploy /opt/kyglxtv3
sudo systemctl restart kyglxtv3
```

### 6.6 安全清理（授权完成后务必执行）

> ⚠️ 私钥文件删除。

```bash
sudo rm -f /opt/kyglxtv3/license_generator.py /opt/kyglxtv3/private_key.pem
```

执行后确认文件已删除：
```bash
ls /opt/kyglxtv3/license_generator.py /opt/kyglxtv3/private_key.pem 2>&1
# 应输出：No such file or directory
```

> 💡 下次续期时再重新复制这两个文件到服务器即可，用完同样删除。

## 七、配置 Nginx（反向代理 + 静态文件）

```bash
sudo tee /etc/nginx/sites-available/kyglxtv3 > /dev/null <<'EOF'
server {
    listen 80;
    server_name localhost;
    client_max_body_size 100M;

    location /static/ {
        alias /opt/kyglxtv3/static/;
    }

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
EOF
```
创建 Nginx 配置文件，并允许最大 100MB 上传。

```bash
sudo ln -s /etc/nginx/sites-available/kyglxtv3 /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```
启用站点并重载 Nginx。

## 八、配置 Gunicorn 系统服务（开机自启、崩溃重启）

```bash
sudo tee /etc/systemd/system/kyglxtv3.service > /dev/null <<EOF
[Unit]
Description=kyglxtv3 Flask App
After=network.target

[Service]
User=xazx
Group=xazx
WorkingDirectory=/opt/kyglxtv3
Environment="PATH=/opt/kyglxtv3/venv/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin"
Environment="UPLOAD_FOLDER=/data/上传的文件"
ExecStartPre=/opt/kyglxtv3/venv/bin/python -c "from license_manager import check_license_or_exit; check_license_or_exit()"
ExecStart=/opt/kyglxtv3/venv/bin/gunicorn --workers=3 --bind=127.0.0.1:8000 app:app
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
```
服务文件包含：
- 使用 `xazx` 用户运行
- 注入 `UPLOAD_FOLDER` 环境变量指向机械硬盘
- `ExecStartPre` 在启动前验证 License，无效则拒绝启动（第一道防线）
- `app.py` 模块级别也内置了 License 校验，Gunicorn 导入时自动触发（第二道防线）
- 崩溃后 5 秒自动重启

```bash
sudo systemctl daemon-reload
sudo systemctl start kyglxtv3
sudo systemctl enable kyglxtv3
sudo systemctl status kyglxtv3
```
启动服务并设置为开机自启，最后检查状态应显示 `active (running)`。

## 十一、上传路径终极修复（软链接）

> 若上传时出现 `Permission denied: '/opt/上传的文件'`，执行下面一条命令即可永久解决：

```bash
sudo rm -rf /opt/上传的文件 && sudo ln -s /data/上传的文件 /opt/上传的文件 && sudo chown -h xazx:xazx /opt/上传的文件 && sudo systemctl restart kyglxtv3
```

**原理**：无论代码默认向 `/opt/上传的文件` 写入什么，软链接都会将数据透明地重定向到机械硬盘 `/data/上传的文件`。

## 十三、常见故障快速修复

| 现象 | 解决命令 |
|------|----------|
| 授权验证失败 / License 无效 | 检查 `license.key` 是否存在：`ls /opt/kyglxtv3/license.key`，重新生成并部署 |
| 授权已过期 | 在管理机重新生成 License，SCP 覆盖后 `sudo systemctl restart kyglxtv3` |
| 设备指纹不匹配 | 重新获取 Ubuntu 指纹（见 6.2），用新指纹生成 License |
| 服务无法启动（License 错误） | `sudo journalctl -u kyglxtv3 --no-pager -n 20` 查看具体原因 |
| 413 Request Entity Too Large | `sudo sed -i '/listen 80;/a\    client_max_body_size 100M;' /etc/nginx/sites-available/kyglxtv3 && sudo nginx -t && sudo systemctl reload nginx` |
| 502 Bad Gateway | `sudo systemctl restart kyglxtv3`，再查日志 `sudo journalctl -u kyglxtv3 --no-pager -n 50` |
| 数据库结构变更后异常 | 运行 `cd /opt/kyglxtv3 && source venv/bin/activate && python oneclick_migrate.py` |
| 网络不通 / SSH 拒绝连接 | 检查防火墙 `sudo ufw status`，确保 `22/tcp` 和 `80/tcp` 为 `ALLOW` |
| Tailscale SSH 无法连接 | 改用传统 SSH：`ssh xazx@局域网IP`，或检查 ACL 规则是否正确 |
